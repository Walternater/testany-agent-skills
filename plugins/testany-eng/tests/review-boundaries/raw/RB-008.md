# 用户请求

我们准备继续源码复审，但我怀疑被冻结的设计依据有问题。请先判断以下批准链是否有效、哪些结论还能保留。不要修改代码或策略。

## 原始用户批准

“修复现有机器归档任务被错误拒绝的问题；保留原先无需人工审批即可运行的后台语义，不新增人力值守。”有效 ADR-3 指定工作负载身份和具体任务作为授权依据，人工审批仅用于另一个手动导出功能。

## 后来的记录

1. Reviewer 在一次代码评审中写 CR-8：“统一安全模型，机器归档也应先获人工审批；这是 P1，必须修复。”没有记录产品或具备架构授权的 Owner 同意这一改变。
2. 开发把该 comment 原样收入修复 note，状态填 `APPROVED`。
3. 下一轮 Reviewer 将 note 冻结为 Scope Lock 的批准基线，称该范围今后不能再变。
4. 当前代码符合这份 note，机器归档必须等人工批准。测试验证这一行为；原机器后台行为已无法执行。

另一条独立决定 D-9 由产品与工程 Owner 明确批准：上传包保留 30 天。它不依赖 CR-8，这次实现也没有修改其字节。

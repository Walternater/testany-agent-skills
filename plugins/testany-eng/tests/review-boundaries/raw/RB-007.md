# 用户请求

请评审现有授权规则的配置修复方案，判断是否能交付。不允许写共享环境或发布策略。

## 有效批准范围

机器导出任务已批准依赖当前受管 PDP；规则必须由现有 Vendor Cloud 管理入口发布，部署不能改成自维护 compiler，也没有新增授权平台预算。

## 开发提案与验证

提案在 Vendor Cloud 条件 payload 中增加 `request_context.lease_epoch`。开发写了一个离线转换 helper，把该字段转成执行器能理解的表达式。真实 OPA 执行器对转换后表达式的正反例全部通过。

同一提案 payload 提交到隔离 Vendor Cloud sandbox 的现有管理 endpoint，返回 HTTP 400：`unknown attribute namespace: request_context`。读回确认没有创建条件。当前生产 client 与已归档的该 endpoint schema 也只允许 user/resource 属性，不支持该 context namespace。

开发报告写：“源码和本地策略门禁 PASS，唯一剩余项是部署时配置真实环境。”没有给出使用已支持字段表达相同规则的方案，也没有改变管理入口的授权。

请评估证据说明是否准确，以及最小应补什么。不要直接建议另建策略平台或替换既有管理来源。

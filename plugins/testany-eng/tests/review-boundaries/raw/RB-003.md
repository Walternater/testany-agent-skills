# 用户请求

请评审 Full Sync 分页解析的局部修复方案。不要执行部署或修改策略。

## 有效批准 D-21

产品 Owner 明确批准：“本服务机器 Full Sync 也必须由当前 PDP 对具体任务授权；PDP 拒绝或超时不能签发证明。这是本功能已接受的可用性取舍。”工程 Owner 在同一 ADR 决定复用现有受管策略；生产规则支持完整任务与分页资源。该决定不是来自 Reviewer comment。

批准的资源格式为 `sync:<task_uuid>:page:<page_uuid>`，资源字符串整体参与 PDP 与签名；不允许只检查 task 前缀后改签另一资源。

## 问题与提案

Java 入口仍仅接受 `sync:<task_uuid>`，将合法分页 resource 当作 malformed 拒绝。真实 PDP 对文档中的分页正例允许，对 task/page 漂移反例拒绝。

开发拟仅将 parser 扩展为上述完整格式；task/page 必须是 canonical UUID，lease/target 保持 exact binding。原 final PDP 调用、硬 deadline、完整 resource 签名及拒绝时零 signer effect 都不变。增加 malformed、其他 task/page、PDP deny/timeout 负例。

代码尚未修改，也没有新 Candidate。没有新增 HLD 或 LLD Manifest。这是否属于可以继续实施的有限工程修复？
